## 1. 目标和最小链路

A 的数据盘空间不足，B 有可用 CPU 与约 5.3 TiB 剩余空间。将 B 作为与 A 平等的执行和存储节点，承接新增自建与 NVIDIA 数据，不搬迁历史文件。

最小链路：**提交任务 → 自建仍在处理机完成 Phase0 → 首次远端写入前选择 A/B → 绑定节点、申请槽位及预留空间 → 上传/下载 → 既有流水线处理 → 校验及帧索引 → 按配置回传 NAS → 页面查询与原节点重试/清理。** NVIDIA 直接进入远端准入，不调用处理机的自建 Phase0。

系统使用者仍从既有页面/API 提交和查看任务，不需要自行选择服务器；运维人员通过部署配置维护两个节点、预算和环境。没有候选节点时任务排队，显示原因。

## 2. 已确认决定

| 编号 | 决定 |
|---|---|
| MN-DEC-01 | 只分流新增数据；历史文件不迁移、不复制，已有远端数据的源保持原节点。 |
| MN-DEC-02 | A、B 平等参与自动选择；有空槽且空间充足者可承接新任务。 |
| MN-DEC-03 | 每节点 3 个执行槽，自建和 NVIDIA 合计最多 3；两节点总上限 6，不表示所有任务一定同时运行。 |
| MN-DEC-04 | 只在首次远端上传、下载或创建运行目录前选择；分配提交后固定节点，后续阶段及重试不跨节点。 |
| MN-DEC-05 | B 沿用 A 的数据目录名与工作层级，只替换根。自建 Phase3 继续原地使用 infer。 |
| MN-DEC-06 | GPU 不参与节点准入。处理机自建 Phase0 继续使用其 GPU；执行节点主要使用 CPU、磁盘和网络。 |
| MN-DEC-07 | 两节点共用 B 的现有模型服务及平台原有模型许可额度，不随执行节点数量翻倍。 |
| MN-DEC-08 | 使用按路线配置的固定任务空间预算。自建预算、NVIDIA 预算和节点安全余量必填，实测后启用，不猜测生产数值。 |
| MN-DEC-09 | 复用 Backend、Orchestrator、代理、租约及发布机制；节点由部署文件管理，不开发节点管理页面。 |
| MN-DEC-10 | 本次只交付文档。角色、群、cron 未绑定，不开始业务开发、远端写入或生产启用。 |

## 3. 当前证据与待实现能力

- 2026-10-12 前序只读核验：A `/data` 约剩 281 GiB，B `/home/sysadmin/data/disk03` 约剩 5.3 TiB。容量为当时快照，上线前必须重新探测。
- 当前用户明确 A 并发配置为 3；代码中的 `RESOURCE_COMPUTE_CAPACITY` 默认 1 不能代替生产配置事实。本轮未读取生产 `.env` 或数据库运行值。
- 现有平台使用单一 `A100_PROXY_URL`；SourceCopy/Artifact 只有路径，没有存储节点标识；PipelineRun 没有执行节点和持久空间占用字段。
- 现有 ResourcePool 已按 executor_id 隔离；A100 资源租约过期会从计数中移除，不能直接用作未知远端写者的持久占用依据。
- NVIDIA 配置和代理环境校验含 A 的固定根，需增加节点 profile，不能仅增加第二个 SSH 地址。
- A 的 8002 是到 B 的 SSH 转发，B 的 8002 是现有模型服务。两条远端路线未发现本地 GPU 执行依赖；具体脚本版本及前提见 [HANDOFF](HANDOFF.md)。
