## 1. 目标与最小链路

把现有 `/bags` 行级“清理”功能扩展到 `dataset_type=nvidia_physicalai`。用户可清理一个已登记的 NVIDIA Chunk：先看到影响范围，确认后异步删除该 Chunk 的数据库业务记录及 A100 专属数据，最终从目录移除；失败可查询和恢复。

**NVIDIA 行 → 只读预览 → 用户逐次确认 → 写入围栏与远端写锁 → 删除 origin、infer、所有专属 run → 核验不存在 → 数据库事务清理与批次历史标记 → 成功移除。**

“删除英伟达数据集”本期按现有删除功能的粒度解释为单行/单 Chunk，不提供整个 Hugging Face 仓库、整批或所有 NVIDIA 数据的一键删除。沿用既有“数据库+A100”范围：NAS 已备份原始数据和已发布 final 保留，弹窗必须说明。上述粒度和保留范围是本次规划采用的兼容决策，用户可以调整；不能把它表述为用户逐项确认过。

## 3. 当前事实与差距

- `_require_self_built_bag`、`build_cleanup_plan` 和 `/bags` 模板均拒绝或隐藏 NVIDIA 清理。既有测试 `test_nvidia_dataset_rejected` 明确覆盖拒绝行为，不能只改按钮。
- NVIDIA 源由 `nvidia_service.create_chunk` 登记，UID 为 `nvidia-chunk-{chunk}`，名称为 `data_sample_chunk{chunk}`，完整身份含 repo、resolved revision、chunk。`source_generation` 已存在，NVIDIA 当前创建未实现清理后推进。
- 当前 `create_chunk/create_submission` 没有接入清理围栏；通用领取、重试与写回已有围栏调用，但需要验证 NVIDIA 缺源/旧代次情形。
- NVIDIA 的 `launch_remote_nvidia` 先创建 run 目录再启动进程，尚未接入现有 Bag writer 锁。自建 writer 的既有验收不能替代 NVIDIA 互斥证据。
- `SubmissionBatch` 保存 JSON run ID 列表；`submission_progress` 只查询仍存在的 run，缺失条目没有“已清理”语义，GET 还会写回派生批次状态。
- NVIDIA NAS 原始副本类型为 `NVIDIA_ORIGIN_NAS`，不符合旧解析器 `NAS_` 前缀；必须显式分类为保留。NVIDIA manifest/结果类型必须按当前 producer 和路径核对。
- 旧 `doc/rosbag-cleanup` 的生产未开放描述属于历史；catalog HANDOFF 有 2026-10-08 用户实际自建清理成功记录。本轮仅核对本地源码，没有重新检查生产状态，不能宣称 NVIDIA 已部署或已验收。

## 4. 用户旅程与文案

1. 开关开启时 `/bags` 的 NVIDIA 行显示“清理数据集”；开关关闭时不显示，直接调用 API 也拒绝。
2. 点击只生成预览。弹窗展示 NVIDIA、Chunk 编号、数据版本、环境，以及删除/保留分类。不会展示租约、锁协议或表名等实现细节。
3. 无活动任务且目标检查完整后可确认；不明归属、目录冲突、A100 不可达时显示具体原因，确认不可用。取消不产生删除。
4. 用户勾选不可撤销说明并确认后快速返回清理编号；刷新可继续查询，重复确认只关联同一操作。
5. 失败保留数据源记录与审计，提供“重试清理”；先对账，再继续原计划，不能扩范围或跳过失败。
6. 全部远端目标不存在且数据库事务成功，才从列表移除。筛选与分页延续既有行为。
7. `/nvidia/batch/{batch_id}` 的对应历史条目显示“已清理”，原 run 详情链接禁用，其他 Chunk 仍可查看和运行。
8. 后续显式提交已删 Chunk 时，预览说明“将重新下载此数据；NAS 保留副本仍在”。用户选择重新导入、使用新请求键后创建新代次；旧批次重放始终只返回历史。

示例弹窗：

> 清理 NVIDIA 数据集：Chunk 33 · 生产环境 · 版本 33f9bf…
>
> 将删除：平台中的数据集信息、处理历史及帧索引；A100 上此 Chunk 的原始下载、解压/推理结果及所有专属运行目录。
>
> 保留：NAS 原始备份和已发布结果、其他 Chunk、共享下载缓存、模型/代码环境、批次历史与清理记录。
>
> 此操作无法由本功能撤销。存在运行任务或无法确认目录归属时不能执行。

## 6. 非目标、失败恢复与停止条件

不做批量删除、回收站、删除 NAS、全局缓存 GC、活动任务强杀、历史污染自动修复或新的权限系统。不重构场景切片调度，不将其任务编号、完成状态、角色绑定复制到本专项。

预览不完整即阻断；确认后部分失败持续保有围栏，不随超时释放；远端已清理但 DB 未提交时只重试 DB。路径/归属矛盾升级人工对账，不能以“看起来属于本 Chunk”放行。

本次停止点是文档一致、需求映射完整、无环任务依赖和五角色接续入口可用。后续开发与本地验收完成后仍停在生产发布门禁；真实远端测试和生产发布分别等用户授权，不自动继续。
