需求包：`rosbag-catalog-scene-foundation`。本次整理仅迁移文档内容归属，不更新实现、验收、部署、授权或任务状态。REQ/AC/TASK沿用原编号，不因拆包重新编号或重新派发。

当前任务状态、派单与角色运行仍由[原唯一TODO](../rosbag-catalog-integration/TODO.md)、[现行启动入口](../rosbag-catalog-integration/SESSION-START.md)和原绑定维护；本包[TODO](TODO.md)只导航，不建立第二份可写任务状态。历史混合正文保留在[整理前归档](../rosbag-catalog-integration/archive/pre-reorganization-20261014/)，其中暂停、待发布等旧描述不作为当前执行指令。

## 1. 目标与边界

平台提供统一Bag数据目录和可配置场景处理服务：每包配置/目录默认→独立场景接收树→稳定性与完整性校验→原子移至ready登记/冻结→正式处理机代理→场景分析/切包→NAS发布→MySQL登记/当前版本→服务API查询、追溯与获取。原始包是追溯依据，切片是主要消费对象。

本包维护场景平台公共契约、原坡道能力和必要容量/兼容防线。三视图、集合查询增量、八步详情与原界面OCR收尾归[界面包](../rosbag-catalog-scene-ui/PRD.md)；水雾适配、专属资料与生产收尾归[水雾包](../rosbag-catalog-spray-pipeline/PRD.md)。本次执行位置调整仅适用于场景识别/切片，自建/NVIDIA既有A100路线不迁移。

每包配置可在上传前通过API提交，也可使用接收目录默认值。配置在incoming阶段解析并绑定，原始包登记时冻结，进入ready后不重新猜测。配置API不传输Bag大文件。

## 4. 统一数据组织

### 4.1 独立维度与派生关系

| 维度 | 含义 | 规则 |
|---|---|---|
| 数据来源 | 既有 self_built、NVIDIA 等分类 | 不将切片当作新来源。 |
| Bag 角色 | 原始包、场景切片；非 ROS2 条目不适用 | 同一记录有明确角色。 |
| 处理用途 | 场景切片、自建数据集，可同时选择 | 用途来自有效提交配置，同一原始包无需复制登记。 |
| 识别场景 | 本次选择的能力及其版本、参数 | 与采集目标、有效场景标签分开保存。 |

一个原始包可对应多个独立子 Bag，每个子包有自己的 ID、文件、topic、指纹、时长和可用状态。血缘记录父包、子包、任务、场景、源时间区间、分析版本及算法配置版本。首期单父多子，不做跨原始包拼接。

Artifact 是生成过程和产物证据，BagRecord 是可查询、可使用的数据入口，二者关联同一份物理文件。SourceCopy 不表达切片关系；识别帧不混入现有 VLA DatasetFrame。

车辆和采集信息由父包继承，基础历史入口的未知值明确为空或未关联，不要求为跑通链路先人工补 CSV。水雾新入口的强制资料另按水雾包REQ-18，不以此处旧入口兼容放宽其要求。采集意图、模型结论、人工标签分别记录来源；选择“识别坡道”不表示原始包或所有子片段都已经是坡道。

### 4.2 文件与清理

切片目录为发布根下的 `<vehicle_key>/<scene_code>/<parent_uid>_<slice_uid>/`。未知车辆用 unassigned；多标签只更新数据库关联，标签/车辆修正不移动已发布文件。测试与生产使用独立根。

Bag 内原始文件不可修改。仅沿用现有 Scanner 对已配置 incoming→ready 的整包原子移动例外；进入 ready 后原始路径不可移动。存在派生关系时，未经适配的旧清理必须在服务端阻断，不因删除父记录而级联删除子包。

## 5. 配置与自动处理规则

- 平台 API 返回可用识别能力和参数说明。历史P0首期仅坡道；后续能力是否可用以已接受注册/实现和实际部署为准，源码分支存在不等于平台注册可用。
- 每包显式用途/场景集合替换对应默认集合，不进行隐式并集；参数使用服务端允许的覆盖项。缺省与空集合的校验详见 DESIGN §3。
- 无有效配置的新接收包可登记待处理，但不猜测用途或自动全场景运行。既有未迁移入口按原规则兼容，不因新功能开关改变已有任务。
- 目录上传、手动和批量登记共用稳定性、完整性及用途路由。绑定完成后配置冻结，后续配置变更不重算历史；重新分析必须显式提交新版本。
- 缺必要 topic 标记不适用；解码失败、无有效输入帧、模型/参考图/配置异常标记失败。有效模型返回无目标为无命中，不创建空 Bag。
- 按能力独立记录进度和结果。后续多场景任务中，单类失败不阻止其他合格结果可用。
- 保留各场景的时间规则及合法重叠，不跨场景合并近似区间。坡道中的 flat 仅保存分析证据，不发布为目标切片。
- 重复扫描、回报、恢复不重复创建任务或子包。新分析成功后按父包+场景切换当前结果；失败保留旧版，成功无命中可切换为空结果。
- 文件校验、数据库登记及当前版本完成前，不作为可用结果展示。文件已发布而入库失败须能对账补登记。
- 子切片不会自动再次识别或进入自建流程；用户需要时显式提交自建处理。历史包不自动全量补跑。

## 6. 服务查询与后续能力

P0 提供可用切片检索、原始包查询、父子追溯、任务结果及 NAS/SMB/rsync 获取信息。默认结果查询仅返回当前可用切片，可显式选择原始包、全部和历史。统一 API 是后续页面和上传工具的共同入口。

三视图、数据类型和流水线详情契约在[界面包设计](../rosbag-catalog-scene-ui/DESIGN.md)。基础层保存标签来源与可审计修订基础；TASK-07界面/人工修订及预览归界面包，状态与启用阶段仍以原TODO为准。

### 6.2 P3 统计口径

以当前有效且可用的切片为默认样本，按场景、车辆和原始采集日期展示切片数量、涉及原始包数及片段累计时长。同一 Bag 在同一统计分组只计一次；多标签可能进入多个场景分组，各组不能直接相加冒充全局总量。

覆盖时长应按同一父包内区间求并集后计算，分别标识“累计片段时长”和“去重覆盖时长”，不把允许重叠的切片累计时长当原始数据覆盖率。人工纠错、下架和版本替换后统计须同步更新或标注刷新时间。

## 7. 容量要求

基础容量治理仍在 P0 完成，但不能演变为独立的大表改造项目：

- 新增高增长表使用 BIGINT；既有 ID/FK 类型、可用空间及预计增长先盘点。对外 Bag UID 保持稳定，低成本兼容的扩容可同批做；需大规模重建/长锁的改造记录到 TASK-15，不阻塞测试环境首个切片。
- 元数据、区间、标签来源和任务明细分层；图片、逐帧结果及大日志只存产物引用，不能灌入 BagRecord。
- 首次迁移建立必要组合索引、唯一约束、父子 FK 和当前版本指针；用途/场景可索引，不靠大 JSON 检索。
- 新 API 使用有界游标、字段投影、回报批次/JSON 限额；用首期小规模数据检查实际 SQL 与分页，不设十万条硬门槛。
- 保留稳定证据身份、时间/版本、路径和摘要，后续可以定位历史，不首期开发通用归档/恢复系统。

完整容量预测、十万/百万规模基线、全文检索引擎、实际冷热迁移与分区/分库分表属于后续任务，只有实测需要时开展。当前实现若确有无法有界执行的查询，需明确限制支持范围或修复，不能以“最小链路”隐瞒风险。BIGINT 不保证性能或无限容量；P0 完成只证明最小工程闭环，不能宣称批量生产容量达标。详见 DESIGN §8。

## 9. 完成定义、材料与跨包责任

基础工程闭环要求正式接收/队列/代理/API全链贯通，真实切片非空可打开，源时间映射和少量内容核验可追溯；mock和单函数成功不能替代真实链路。生产质量与容量分别验收，不因单包工程闭环宣称准确率、吞吐或扩量达标。

TASK-01～06及子任务、08～15、16A/16B保留原任务号与既有接受证据，未完成项按原TODO状态接续，不在本文件复述实时状态。TASK-12只是其他场景聚合/路线图，提前的12S水雾子集归水雾包。

共同契约以[本包DESIGN](DESIGN.md)为唯一正文来源。界面包引用基础16A/16B及API/发布证据；水雾12S-A引用16A/03，12S-B引用04A/B/09，12S-C引用16B和12S-A/B的已接受固定产物。跨包引用不能代替实际固定SHA和接受证据。

不含模型训练、多源拼接、切片递归、历史CSV全量导入、新增网页大文件传输。生产迁移和启用需当次实际授权及发布门禁。
